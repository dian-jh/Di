# 执行 AI 的逐单元操作规则

> 状态：供未来迁移使用的操作规程，不代表迁移已实施。阶段定义以 [execution-plan.md](execution-plan.md) 为准；接口只在 [architecture.md](architecture.md) 定义；验收以 [validation-and-release.md](validation-and-release.md) 为准。本文件只规定如何领取、执行和交接任务。

## 开始时使用的指令

可以将下面这段交给执行 AI：

```text
在当前迁移分支继续 Di 的 TypeScript Core 迁移。
先读 AGENTS.md、docs/README.md、docs/migration/typescript-core/README.md
和 docs/migration/typescript-core/operator-guide.md。
检查 git status、当前分支、最新提交及已有迁移进度，不切换旧分支、不清理用户文件。
本次只领取第一个依赖已通过的未完成任务卡，不同时重写多个阶段。
按任务卡读取专题和固定 C# 基线源码；先写业务测试并确认 red，再实现到 green。
保存真实命令、退出码及关键断言结果，提交一个可编译的逻辑单元。
未通过的门槛保持未完成；缺少决策或平台能力时记录具体阻塞，不伪造实现或跳过测试。
文档内的 TS 代码片段可能只展示接口，必须补全真实定义并编译，不可直接视为完整模块。
```

## 每次领取任务前

1. 从仓库根运行 `git status --short`、`git branch --show-current`、`git log -3 --oneline`。应在 `migration/typescript-core` 或从该分支创建的实施分支；不要在 `feature/loop` 写迁移。
2. 检查已完成提交与实际文件。没有测试记录的任务只能标为“待验证”，不能因为存在同名文件就认定完成。
3. P0 后由实施者创建 `docs/migration/typescript-core/progress.md`（目前不存在），只保存简短状态表与证据位置，不复制专题契约。每行包含任务 ID、依赖、状态、实现提交、验证命令和退出码、阻塞点。详细输出存于实施任务的测试产物，不把 token 或个人日志提交进仓库。
4. 选择一个依赖已完成的任务，先写任务卡。遇到文档冲突先检查固定基线和对应契约；不能自行挑较容易通过的一条。

状态只用 `todo`、`in_progress`、`blocked`、`verified`。`blocked` 不等于完成；没有在当前版本验证过的 `verified` 项，在相关代码改变后必须重新检查。

## 当前可执行性与预研任务

P0 和最小 P1 可以直接开始；本文档不是无需判断即可一次生成全部代码的规格。下列能力尚未做 TS 平台探针，应先拆成预研任务。执行 AI 只按候选的真实 API 做小型探针，不能一边猜选型一边接入主流程；探针失败时把结果交给能处理架构/平台问题的审查者，再继续依赖任务。

| 预研任务 ID | 依赖方 | 交付证据 |
|---|---|---|
| P4-regex-probe | grep 实现 | 对照既有 .NET 表达式逐项比较匹配；证明超时能终止 worker；列出未支持语法和差异，具体契约见工具专题 |
| P4-win-process-probe | shell/powershell/python | Windows 子孙进程 marker、取消/超时后的进程和管道清理记录；验证明确的进程树终止实现 |
| P4-win-encoding-probe | Windows shell 输出 | 真实 OEM code page 获取、支持性探测、分片多字节/混合编码输入输出与错误路径 |
| P8-auth-storage-probe | ChatGPT 登录与刷新 | 两个独立进程竞争同一锁、持锁进程退出后的行为、Unix mode/Windows ACL 回读、失败不覆盖旧凭据；具体契约见模型认证专题 |

预研并未在本次文档审查中完成，不能在进度表预先标绿。较弱模型可以执行已冻结契约的任务卡；这些预研的选型结论和最终发布验收仍需要独立复核。

## 一张任务卡的必填项

```text
ID: P4-file-read（示例，由实施者为具体单元编号）
输入: 固定基线源码路径、对应旧测试、专题小节、已完成依赖
行为: 用户/调用方给定什么输入，应观察到什么输出或副作用
范围: 本次允许修改的目标文件及测试文件
红测: 将运行的命令、缺失行为应触发的具体断言
实现: 最小实现，不加入无关功能
绿测: 同一测试、包级类型检查、受影响回归测试
交付: 提交号、实际命令/退出码、已覆盖场景、未覆盖平台、下一任务
```

测试文件不存在或导出缺失可以作为脚手架首次红测；后续业务单元的 red 必须说明业务行为缺失，不能一直用路径错误、依赖没装好或语法错误充当 TDD 证据。fixture 的预期来自旧实现、已核实测试或明确的迁移差异，不能从刚写的 TS 输出反向生成预期再宣称兼容。

P1 将专题草图落实为真正可编译的公开类型后，后续任务必须直接导入这些类型，不各自改名或复制声明。需要改接口时，由集成者在同一单元更新定义、消费者、测试和文档，并重跑受影响包；不得用类型断言掩盖不兼容。`@di/ai` 的消息和工具 schema 类型不能引用 `@di/agent` 的执行器类型。

## 建议拆分粒度

下表是每阶段内部的执行次序，不替代阶段的输入和门槛。每个分号分隔项通常是一张任务卡；如果仍需同时处理多种独立故障，再拆小。

| 阶段 | 内部顺序 |
|---|---|
| P0 | 验证参考提交与工作区；隔离基线测试；建立行为台账与进度文件 |
| P1 | 根 workspace 与原 TUI 回归；最小公开类型/编译导出；假模型/假工具；首组跨语言 fixture |
| P2 | 无工具答案；一次工具往返；多工具批；迭代上限；软停与硬取消；历史与预算；观察事件和 checkpoint hook 的不同错误策略 |
| P3 | provider chunk assembler；HTTP/SSE framing；DeepSeek 请求/响应翻译；usage/cost；重试与超时 |
| P4 | read/write/edit；文件枚举；搜索与可终止正则；输出收集；进程树生命周期；持久 shell；平台编码 |
| P5 | JSONL writer/codec；reader/校验；恢复状态机；同进程恢复；child test host 崩溃；统计 |
| P6 | 配置合并；skill parser/discovery；matcher/activation；命令解析/注册；模型选择；CLI 参数/模式；日志 |
| P7 | headless composition；print/json；RPC writer/reader；busy/cancel/shutdown；原 TUI 对 TS RPC；真实 CLI crash/resume |
| P8 | 合成认证端点；凭据权限与跨进程事务；ChatGPT 翻译/流/回放；并发刷新与故障；provider 切换 |
| P9 | TUI port 抽取；local adapter 差分；隔离打包安装；全量兼容/平台/长任务验收；回退演练；更新权威文档 |

P2 使用假模型，不等待 P3 网络实现；P5 使用真实 session store 与测试宿主，不等待 P7 CLI。P6 的纯解析可以先做，依赖真实 session/model 的命令集成留到 P7。具体依赖未满足时，只交付独立子单元，不标整个阶段通过。

## 必须停止当前单元并记录的情况

“停止”指不推进依赖该能力的任务，可以继续其它独立任务；不要求重复询问已授权的常规修改。

- 不能读取固定 C# 基线：先恢复参考可读性，不凭记忆补旧行为。
- 接口缺少类型或两个文档定义冲突：定位唯一权威，修订并编译最小契约，再让依赖方使用；禁止 `any`、空实现、固定成功返回绕过。
- Windows ACL、进程树、编码或正则兼容尚未证实：相应平台 gate 保持未通过。不得以 Linux 测试代替，也不得降低原工具能力后宣称完全等价。
- 需要新增依赖：记录用途、固定版本、公开 API、许可证、最低 Node/平台测试；先验证最小探针，再纳入主链路。原生 helper 必须一并有构建、分发、失败路径，不能只有伪函数名。
- checkpoint 出现未知结果：保留文件和诊断，拒绝自动重放；不得为了测试变绿删除 started 或补造 completed。
- 真实平台、真实 provider 或十小时墙钟测试未运行：写“未验证”并保留发布门槛；加速假模型测试不能替代这些证据。

## 验证与交接的判定

命令必须从实际 manifest/脚本确认。未来的脚本名仅是要求，在创建前不能直接照抄并报告通过。PowerShell 调用 npm 使用 `npm.cmd`，每条验证命令单独检查 `$LASTEXITCODE`；不要只检查一串命令中最后一条的退出码。原有 C# 测试只证明 reference 没变，不能证明 TS 实现正确。

编译依赖包后再检查消费者；详细顺序按架构文档。至少运行本单元业务测试、对应包 typecheck/test，以及改动影响到的 TUI/兼容测试。不为无关文档修订重复运行生产测试。

一次交接须让下一 AI 不依赖聊天记忆：更新进度行，记录当前提交、下一张任务卡、关键命令和失败原因。恢复工作先验证现有状态，再继续下一项；不得因为上文出现“完成”二字就跳过尚未通过的 gate。全部 gate 满足前不能删除 C# reference、覆盖本机安装版或宣布迁移完成。
